# Basemap options for the game map

Research for [#110](https://github.com/sschorer/manhunt/issues/110), part of the accessible UI redesign ([#105](https://github.com/sschorer/manhunt/issues/105)). This file lists facts and options. The choice belongs to a later ticket.

Checked on 2026-09-29 against the providers' own terms, pricing and docs, plus live response headers (fetched with `curl`). Prices and quotas change, so check the linked page again before deciding.

## Starting point in this repo

- `client/src/game/GameMap.tsx` uses MapLibre GL JS (`maplibre-gl` ^5.24) with an inline raster style that points at `https://tile.openstreetmap.org/{z}/{x}/{y}.png`. Attribution is `© OpenStreetMap contributors` in a compact attribution control. A code comment already says OSM's tiles are not for production traffic.
- The markers and rings are drawn on top in teal `#24e3c6`, red `#ff4242` and amber `#e0b341`. The UI is dark (`theme_color` `#06080c`). The light OSM raster clashes with that.
- `client/vite.config.ts` sets up `vite-plugin-pwa` / Workbox so that it precaches only the app shell. There is **no `runtimeCaching` rule**, so the service worker does not cache any tiles today. Tiles live only in the browser's HTTP cache, and the map has no offline tiles.
- The Docker target's asset Worker (`server/assets/assetWorker.ts`) always answers with the full file and status `200`. It ignores `Range` headers. This matters for PMTiles (see below).
- `deploy/Caddyfile` sends `Referrer-Policy: strict-origin-when-cross-origin`. Cross-origin tile requests therefore carry the origin as `Referer`. That is enough for OSM's Referer rule and for referrer or origin-based key restrictions (Stadia, MapTiler, CARTO).
- There is no Content-Security-Policy today. If one is added later, `connect-src` has to allow the tile, style, glyph and sprite hosts.
- **Rough load estimate (inference, not measured):** at zoom 15 a tile covers about 0.75 km at 50° latitude. A play area of a few km² plus panning needs roughly 100–400 tile requests per phone per game. A handful of 2–6 player games a week comes to a few thousand to low tens of thousands of tile requests a month.

## Notes behind the table

### Legibility in sunlight, and room for colour-blind-safe markers

- All the ready-made dark styles are designed as muted backgrounds. CARTO Dark Matter is "a dark gray map (suited for polygon/line data)", and Stadia's Alidade Smooth Dark is meant to "stay out of the way". That makes the markers stand out, but the roads and labels stay low-contrast, which suits a desk better than bright sun.
- Options with a **vector style we control** (OpenFreeMap with a customised style JSON, Protomaps flavours, and paid tiers of MapTiler and Stadia) can raise road and label contrast, and can keep basemap hues out of the colours the markers and rings use. Raster options (OSM, CARTO raster) only allow whole-image filters.
- Stamen Toner (Stadia) is the only ready-made high-contrast black-and-white style found. It needs a Stadia account.

### API keys in a public repo

- A browser map key is always visible in the shipped JS. Providers protect it with origin or domain restrictions, not secrecy: MapTiler uses "Allowed HTTP origins", Stadia uses domain auth with no key at all, Protomaps uses a per-key CORS list, and CARTO uses per-customer keys.
- ADR-0008 bans secrets and account data in the repo. A key would have to come in at deploy time: a Vite `VITE_*` variable at build time does not fit, because the release is a **prebuilt** file and a GHCR image. A runtime value (for example a Worker var or env served to the client) would fit. The Docker config (`config.capnp` `fromEnvironment`) and the wrangler `vars` template would both need it, which keeps parity but adds config.
- Every self-hosted Docker operator would need **their own** provider account, because domain and origin restrictions are per deployment. Key-free options (OpenFreeMap, self-hosted Protomaps) avoid this.

### Cloudflare specifics

- Workers Static Assets: requests are "free and unlimited". Paths matched by `run_worker_first` invoke the Worker and count towards 100k requests a day, and on the free plan get `429` once over. The free plan allows 25 MiB per file and 20,000 files per version.
- Range support in Workers Static Assets is **not documented**. A workers-sdk issue records Pages answering Range requests with `200`. The Workers Cache API does its own range slicing, and `cache.put` throws on `206`. A spike is needed before relying on a `.pmtiles` file as a static asset. Serving z/x/y tiles as individual static files avoids the question.
- Protomaps' own Cloudflare guide uses R2 plus a Worker and warns R2 can have 500 ms or more latency on cache misses. It also says the cache only works on a custom domain, not `workers.dev`. R2 has no counterpart in the Docker image, so it would break the one-config parity of ADR-0005.

### PWA caching specifics

- Cross-origin runtime caching in Workbox: opaque (`no-cors`) responses count about 7 MB each against quota in Chrome. MapLibre fetches tiles with CORS, and every provider probed sends `Access-Control-Allow-Origin: *`, so the responses are not opaque.
- Per-provider rules on client caching differ: OSM says follow the headers and never prefetch or build offline archives, Stadia allows the header lifetime or 7 days, CARTO allows 30 days at most, and MapTiler allows a "temporary personal cache". A `CacheFirst` rule with an `ExpirationPlugin` (`maxEntries`, `maxAgeSeconds`) can respect these limits. Prefetching the play area for offline use is only clearly allowed with self-hosted data, and Stadia allows up to 100 MB only in a mobile application.

## Implications for Manhunt

- **No key, no account, same on both targets:** only **OpenFreeMap** (public instance) and **self-hosted Protomaps** qualify. Everything else needs an account per deployment and a runtime key or domain setup, which adds work for Docker operators and touches the ADR-0008 release config.
- **OpenFreeMap is the smallest change:** replace the inline OSM style with a style JSON. It works worldwide, is free with no quota, and allows commercial use. For sunlight contrast, the Dark style can be customised into a style JSON bundled with the PWA while still using OFM tiles. The risk is a donation-run service with no SLA, which is the same class of risk as today's OSM tiles but with a policy that allows this use.
- **Self-hosted Protomaps gives the most control, but coverage is limited:** full colour control through `@protomaps/basemaps` flavours, and full offline and PWA freedom. However, the map covers only the extract we ship, and games can happen anywhere. It also needs Range handling (Docker asset Worker, and unverified on Workers Static Assets) or conversion to individual tile files, plus hosted glyphs and sprites.
- **Hosted free tiers are not suitable as a default:** MapTiler, Stadia and the Protomaps API forbid commercial use on their free plans, and MapTiler and Stadia pause service at the quota. They would also make every self-hoster sign up. They remain options if an operator wants a specific style such as Stamen Toner.
- **OSM, directly or via a proxy, is ruled out for production** by its own policy (no offline or prefetch, proxy not recommended, no SLA) and offers no designed dark style.
- **Whatever is chosen:** add a Workbox `runtimeCaching` rule for tiles within the chosen provider's caching limits, keep the provider's attribution in MapLibre's attribution control, and check the marker and ring colours for contrast against the chosen basemap.
